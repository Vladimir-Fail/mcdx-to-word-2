# Проект: экспорт формул из Mathcad 15 в Microsoft Word

## Цель проекта
Написать программу `mathcad_word.py` (в корне репозитория). При работе изменять
только её или добавлять дополнительные файлы. Программа читает файлы Mathcad 15
(`.xmcd` — по сути ZIP с XML внутри), разбирает математическое содержимое и
экспортирует формулы в документ Word (`result_Mathcad.docx`) с использованием
шаблона стилей. Есть GUI (tkinter) с drag-and-drop выбором входного файла и
шаблона.

## Структура репозитория
- `mathcad_word.py` — основная (и единственная рабочая) программа.
- `проверка/` — тестовые файлы Mathcad:
  - `ЭМПП_ТР2 — копия.xmcd` — пример с матрицами (D1, A1, вектор Jp и т.д.);
  - `к лр1.xmcd`, `лр3 моя.xmcd`, `Расчетный_файл_Mathcad.xmcd` — примеры
    с комплексными числами и полярной записью углов;
  - `Результат_Mathcad.docx` — пример полученного документа Word.
- `шаблон/Шаблон стилей.docx` — шаблон стилей Word для экспорта.
- `старые/` — легаси-версии скриптов (не использовать как основу):
  «фулл рабочий от гпт.py», «от гемини, не работают индексы...py».
- `README.md` — краткое описание для пользователя.

## Архитектура mathcad_word.py
- `MathcadParser` — разбор XML Mathcad → LaTeX/Markdown:
  - `process_file` — открывает .xmcd, обходит регионы/формулы;
  - `parse_node_to_latex` — рекурсивный разбор любого узла выражения;
  - `parse_matrix_node` / `build_matrix_latex` — матрицы (в т.ч. разбиение
    широких матриц на колонки, чтобы не выходить за границы страницы Word);
  - `parse_complex` / `calculate_complex_polar` — комплексные числа;
  - `is_euler_base` / `extract_polar_angle_degrees` / `format_angle_symbol` —
    распознавание и замена экспоненциальной записи угла;
  - `format_num` — числовое форматирование (запятая как десятичный разделитель).
- `WordConverter` — конвертация Markdown+LaTeX → docx через `pypandoc`
  (с проверкой наличия pandoc) и применением шаблона стилей.
- `ConverterApp` — GUI: выбор файлов, настройка округления, лог, запуск.

## Принципы экспорта Mathcad → Word
1. **Округление**: количество значащих цифр настраивается в GUI
   (`sig_figs_small` / `sig_figs_large` в коде по умолчанию 4 / 8).
2. **Комплексные числа**: при выводе всегда переводятся в полярную форму
   `|z|∠φ°` (модуль и угол в градусах).
3. **Мнимая единица j/i**: поддерживается оба варианта — символ берётся из атрибута
   `symbol` узла `<imag>` в XML Mathcad (пользовательский Mathcad настроен на
   `j`). В полярной форме символ исчезает, поэтому расхождений нет; в
   алгебраических выражениях выводится именно тот символ, что в файле.
4. **Экспоненциальная запись угла**: конструкция вида
   `⋅e^(1j·deg·φ)` (основание `e`, в показателе произведения `1j`/`1i` и `deg`,
   порядок множителей любой) заменяется на `∠φ°` БЕЗ пробела между знаком угла
   и числом (`\angle{φ}^{\circ}`). Если перед конструкцией нет числового или
   буквенного множителя, автоматически добавляется единица:
   `e^(1j·deg·30)` → `1∠30°`.
5. **Матрицы**: распознаются XML-узлы матриц Mathcad, каждая ячейка парсится
   рекурсивно (включая комплексные числа в ячейках → полярная форма), вывод
   через `\begin{bmatrix}...\end{bmatrix}`; слишком широкие матрицы
   разбиваются на несколько блоков.
6. **Единицы измерения**: множители-единицы (например `deg` вне конструкции
   угла) распознаются и корректно отображаются, не ломают разбор.
7. **Формулы-вычисления** (`eval`/`:=` с численным результатом) обрабатываются
   отдельно (`parse_eval_to_latex`) — результат форматируется с учётом
   значащих цифр.

## Как запустить / проверить
```bash
pip install pypandoc tkinterdnd2        # tkinterdnd2 опционален (drag-and-drop)
# нужен установленный pandoc (WordConverter.check_pandoc подскажет)
python mathcad_word.py                  # откроется GUI
```
Быстрая проверка разбора без GUI:
```python
from mathcad_word import MathcadParser
latex = MathcadParser.process_file("проверка/к лр1.xmcd")  # список формул в LaTeX
```
Тестовые прогоны делать на файлах из `проверка/`; ожидаемый артефакт —
`Результат_Mathcad.docx`.

## Правила работы
- Менять только `mathcad_word.py` (или добавлять новые файлы), не трогать
  содержимое `проверка/`, `шаблон/`, `старые/`.
- После изменений проверять компиляцию (`python -m py_compile`) и прогон на
  тестовых .xmcd, особенно регрессии: матрицы, полярная запись ∠, j/i,
  обычные степени (не должны превратиться в углы).
